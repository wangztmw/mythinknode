# CLI 输入 + 心跳频率修复

> 创建时间：2026-08-14 16:25
> 状态：规划中

## 要做什么

两件事：

1. **降渲染心跳频率**：`thinking_tick` 心跳从 100ms 降到 1000ms，`pollEvents` 轮询从 80ms 降到 1000ms，对齐 Claude Code 的 1s 节奏，把渲染频率从 12.5Hz 降到 1Hz。
2. **重新设计输入层**：绕过 readline 的 terminal 行编辑，自己累积输入，支持**一行几万字**和**粘贴几万行**两种大输入场景。

## 为什么做

- **心跳过高**：实测 12.5Hz 渲染（Claude Code 的 12.5 倍）。高频 `\r` 覆写刺激 Terminal.app 的 SwiftUI 渲染层，提高其 SIGSEGV 崩溃概率。多 Agent 时心跳 ×N 压力更大。
- **输入层两个致命限制**（同一根因：readline 是「单行 + 行编辑」模型）：
  - 多行粘贴：`line` 事件按 `\n` 触发，粘贴几万行触发几万次，只取第一行，丢 99.99%。
  - 超长单行：terminal 模式逐字符重绘，一行几万字 = O(n²) 卡死。

## 预期结果

- 渲染频率降到 1Hz，秒数显示仍正常（1s 一跳，体验无损）
- 单个输入能容纳几万行 / 一行几万个字，不丢不卡
- Terminal 崩溃概率显著下降
