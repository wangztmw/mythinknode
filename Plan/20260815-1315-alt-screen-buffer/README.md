# 备用屏 + 滚动缓冲 — 程序接管屏幕渲染

> 创建时间：2026-08-15 13:15
> 状态：规划中

## 要做什么

用 alternate screen（备用屏）接管整个屏幕渲染，程序自建大内存缓冲保存全部对话历史，屏幕只显示"最近 N 行 + 当前输入"，支持鼠标滚轮直接上下滑动回看历史。

## 为什么做

Terminal.app 的 CoreGraphics/Metal 渲染层有 malloc 内存损坏 bug（5 份崩溃报告佐证）。当「历史 + 多行输入」同时可见、屏幕内容复杂时，Terminal 每次重绘都可能踩雷崩溃。

根治方向：**程序完全控制屏幕内容**——不让 Terminal 自由累积复杂历史，而是程序自己维护缓冲、自己决定屏幕上显示什么。这等价于 tmux/less/Claude Code(Ink) 的模型。

## 预期结果

- 程序用 alternate screen 接管屏幕
- 内存缓冲保存全部历史（不丢）
- 屏幕只显示最近 N 行 + 当前输入（内容可控，不复杂到崩）
- 鼠标滚轮直接上下滑动回看历史（不是 /history 命令）
- 退出时恢复主屏

## 权衡（必须心里有数）

- alternate screen 牺牲 Terminal 原生 scrollback——历史进程序自己的内存缓冲，滚动由程序自己实现
- 这是大改动：要重写渲染层（输出也要进缓冲）
