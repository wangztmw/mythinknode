## 用途

专门测试 CLI 输入/输出层。核心关注：多行粘贴、超长单行、中文 IME、光标编辑、折行、prompt 叠加、Terminal 崩溃。

## 最终架构（自建内容管理）

**彻底绕开 readline，raw mode + 自管 stdin**。这是所有修复的共同基础。

```
raw mode（保 IME composition 状态机）
  + process.stdin 直接监听 data 事件，累积原始字节
  + chars 字符数组（code point 分割，正确处理中文双宽 + emoji）
  + cursor 光标位置
  + 追加 O(1) 不重绘（超长行不卡的关键）
  + 编辑操作（方向键/退格/插入）才重绘整块
  + bracketed paste 区分"粘贴换行"和"回车提交"
  + 回车提交（非 debounce 自动提交）
```

## 调查历程（按时间倒序）

### 7. 方向键/删除键"复制换行"（2026-08-15）

**现象**：输入超长内容折行成多行后，按方向键/删除键，prompt + 内容反复叠加。

**根因**：`redraw()` 用 `\r` 只回到**当前行**行首，但内容折行成 N 行时屏幕光标在第 N 行，`\r` 回到第 N 行、`\x1b[J` 只清第 N 行及以下——上面 N-1 行旧内容残留，每次重绘叠加一份。

**修复**：维护 `renderedLines`（屏幕渲染行数），redraw 前先上移 `renderedLines-1` 行回到输入块第一行，再清屏重写。

**关键细节**：ANSI CSI 参数为 0 或省略会默认成 1，所以 `\x1b[0A` = 上移 1 行而非 0 行，必须用 `if (n > 0)` 守卫。

### 6. 粘贴大段文本丢内容（2026-08-15）

**现象**：粘贴几十行文本，内容只保留最后一行，其余丢失。

**根因**（模拟实验精确复现）：粘贴大段多行时，Node 把数据分帧，**换行符 `\r` 恰好落在帧边界被单独切出**，而代码把"单独的 `\r`"误判成"回车提交"，导致内容一行行被 settle 切碎。

**修复**：启用 bracketed paste（`\x1b[?2004h`），终端用 `\x1b[200~`/`\x1b[201~` 包裹粘贴内容，程序据此可靠区分"粘贴换行"和"回车提交"。

**验证数据**：
```
[chunk#0] bracketed开始=true 内容="\x1b[200~..."
[chunk#1] bracketed结束=true
[chunk#2] 长度1 内容="\r"  ← 这才是用户按的回车
```

### 5. 豆包输入法自动提交（2026-08-15）

**现象**：豆包输入法打完一句话，自动开始思考，用户还想补充内容却来不及。

**根因**：debounce 500ms 自动提交，打字时的自然停顿被误判成"输入结束"。

**修复**：去掉 debounce 自动提交，改为**回车提交**。用户明确按回车才提交，想补就继续补。

### 4. 豆包输入法卡死（IME 回归，2026-08-15）

**现象**：terminal: false 下豆包输入法输入：折行线出来 → 卡住 → 字消失 → 堵住无法输入。

**根因**（有现场证据）：
1. `sample 35782` 抓栈：主线程卡在 `uv_run → uv__io_poll → kevent`，node 事件循环健康空转等 I/O，非死锁非死循环非崩溃。
2. `lsof`：stdin/stdout 都指向 /dev/ttys012，进程正常持有 tty。
3. 结论：node 进程没问题，字符根本没传到 stdin。canonical mode 破坏了 IME composition 状态机需要的 raw mode 环境。

**修复**：terminal: false → raw mode。

**教训**：中文 IME 依赖 raw mode，这是硬约束。诊断"卡住"要先用 sample 抓栈确认卡在哪一层。

### 3. 超长单行 O(n²) 卡死（2026-08-15）

**现象**：readline terminal: true 下，5 万字单行卡死。

**根因**：readline 逐字符 `_refreshLine` 回显重绘整行，O(n²)。

**实测证据**：pty 测试 5 万字单行，120s 超时卡死。

**修复**：自管 stdin，追加式 echo O(1)，不做逐字符重绘。

### 2. 粘贴多行丢行 + 空行切碎（2026-08-14）

**现象**：粘贴多行只取第一行；空行立即 settle 导致含空行文本被切碎。

**根因**：readline 单行模型；空行 settle 规则有害。

**修复**：多行累积；去掉空行立即 settle。

### 1. 心跳频率过高（2026-08-14）

**现象**：多 Agent 时卡顿，Terminal 崩溃十几次。

**根因**：渲染 12.5Hz（Claude Code 的 12.5 倍），高频 `\r` 覆写刺激 Terminal SwiftUI 渲染层。

**修复**：心跳 100ms→1000ms，轮询 80ms→1000ms，对齐 Claude Code 1Hz 节奏。

## 关键教训

1. **自建内容管理是基础**：raw mode + 自管 stdin + 追加 O(1) 是"怎么都不崩溃"的兜底。所有其他修复（IME/粘贴/光标）都建立在这个基础上。
2. **区分"粘贴换行"和"回车提交"必须用 bracketed paste**：靠"单独 `\r` 成 chunk"这种传输层细节不可靠，分帧边界不确定。
3. **多行重绘必须先上移回第一行**：`\r` 只回当前行，折行多行后必须用 `renderedLines` 上移。
4. **"卡住"先抓栈定位层**：node 进程卡在 kevent 等 I/O = 终端/IME 层问题，不是 node 死锁。
5. **ANSI 陷阱**：CSI 参数 0 = 默认 1，`\x1b[0A` 会误上移 1 行。
