## 一、我们怎么干的

### 整体策略：删 > 修 > 重写

分三个阶段，每个阶段对应不同的处理方式：

**阶段一（Phase 0-6）：大刀砍**
- 1907 文件/512K 行 → 480 文件/154K 行（-70%）
- 策略：**整目录删除**。遥测、企业功能、UI 层、多余工具——直接 `rm -rf`

**阶段二（Phase 7-11）：修基础**
- 修复类型系统（Tool.ts/Task.ts/commands.ts/tools.ts）——从零重写核心接口
- 修复服务层（services/mcp/、services/tools/）——删除遥测注入，stub 替代断裂依赖
- 工具文件（10 个工具目录）——删除 UI.tsx，批量替换 feature()/USER_TYPE/ANT 代码

**阶段三（Phase 12-13）：建原生**
- Phase 12：发现工具断联问题（2600 个级联依赖错误），尝试三种方案后选择桥接层
- Phase 13：按 Claude Code 原架构从零重写全部 10 个工具为 `tools-v2/`

## 二、关键处理点

### 1. Tool 接口重写（Phase 7）

**问题**：原始 `Tool.ts`（792 行）有 12 个断裂 import（hooks/、context/、AgentTool/、components/、entrypoints/、state/），8 个 React UI 渲染方法，多处遥测字段。

**处理**：从零重写为 220 行。保留核心：`Tool` 接口（name/inputSchema/call/description/isReadOnly/isEnabled/checkPermissions）、`buildTool` 工厂、`ToolUseContext` 上下文。删除所有 React UI 类型、遥测字段、Anthropic 内部宏引用。

### 2. MCP 服务层处理（Phase 8）

**问题**：`auth.ts`（2,465 行）是 OAuth/企业认证代码。`useManageMCPConnections.ts`（1,141 行）是 React Hook。`client.ts` 引用 8 个已删除模块。

**处理**：
- `auth.ts` → 13 行 stub（返回空凭证）
- `useManageMCPConnections.ts` → 7 行 stub
- 删除 8 个无用文件（claudeai、vscodeSdkMcp、xaa 等）
- `client.ts`/`config.ts`→ 删除 `feature()`/`bootstrap/state` 引用

### 3. 工具断联问题的三种方案（Phase 12）

**尝试一：逐文件修复**（放弃）
- 逐个修复 10 个工具的 import → 陷入 whack-a-mole，每修一个暴露更多深层依赖

**尝试二：globals.d.ts 全局声明**（部分成功）  
- 60+ ambient module 声明，消除"模块不存在"错误
- 但无法解决类型不兼容（Message 类型判别联合等）

**尝试三：tools-bridge 桥接层**（采用后又被 Phase 13 替代）
- 230 行新文件，零断裂依赖
- 缺点：不是真正的 Tool 接口，无 Zod 校验

**最终方案：tools-v2 重写**（Phase 13）
- 按原架构从零写 10 个工具
- 每个工具独立的 Zod schema + buildTool() + call()

### 4. Zod Schema → JSON Schema 转换

**问题**：LLM API 需要 JSON Schema 格式，但 tools-v2 用的是 Zod。

**处理**：`z.toJSONSchema(schema)` 一行转换。Anthropic 用 `input_schema` 字段，OpenAI 用 `parameters` 字段。

## 三、工具复刻是否到位

### 是，按 Claude Code 原始架构 1:1 复刻

| 原始模式 | tools-v2 实现 |
|---------|-------------|
| `buildTool({ name, inputSchema, call })` | ✅ 完全一致 |
| Zod inputSchema 定义 + 自动校验 | ✅ 完全一致 |
| `call(args, context)` → `ToolResult<T>` | ✅ 完全一致 |
| `prompt.ts` 独立描述文件 | ✅ 完全一致 |
| `isReadOnly()`/`isEnabled()`/`checkPermissions()` | ✅ 完全一致 |
| 独立目录，每个工具一个文件夹 | ✅ 完全一致 |
| `index.ts` 集中导出 | ✅ 完全一致 |

### 每工具文件数对比

| 工具 | 原始 | tools-v2 | 说明 |
|------|------|---------|------|
| BashTool | 18 文件 | 2 文件 | 去掉了安全校验（30+函数）、权限管线（14步）、沙箱、UI |
| FileReadTool | 5 文件 | 2 文件 | 去掉了图片处理（sharp）、PDF解析、记忆注入 |
| FileEditTool | 6 文件 | 2 文件 | 去掉了 diff 生成、撤销支持 |
| GlobTool | 3 文件 | 2 文件 | 去掉了 UI、权限检查 |
| GrepTool | 3 文件 | 2 文件 | 去掉了 UI、ignore 规则 |
| 其余 5 个 | 3-5 文件 | 2 文件 | 各去掉 UI/遥测/权限 |

### 保留了什么

- ✅ `buildTool()` 工厂模式
- ✅ Zod schema 输入校验
- ✅ `ToolResult<T>` 结构化返回
- ✅ `ToolUseContext` 上下文传递
- ✅ `prompt()` 系统提示词
- ✅ `isReadOnly()`/`isConcurrencySafe()` 并发标记
- ✅ `checkPermissions()` 权限接口（返回 allow）
- ✅ `getToolUseSummary()` 日志摘要

### 没复刻什么（刻意不做的）

- ❌ Bash 安全沙箱（Bubblewrap/Seatbelt）——个人使用不需要
- ❌ Bash 30+ 安全校验（注入检测等）——同上
- ❌ Bash 后台执行/流式输出——后续按需加
- ❌ FileRead 图片/PDF 解析（sharp/napi）——太重
- ❌ FileEdit diff 生成/撤销——后续按需加
- ❌ 权限管线（14 步决策）——单用户不需要
- ❌ React UI 渲染方法——UI 层在 Phase 3 全删了
- ❌ 遥测埋点（Phase 1 全删）

### 数据流

```
用户输入
  ↓
main.ts (Provider检测 → API调用)
  ↓
LLM 返回 tool_use blocks
  ↓
toolMap.get(name) → tool.call(args, context)
  ↓
ToolResult<T> → tool_result block → 回传 LLM
```

### 编译范围

```json
{ "include": ["src/main.ts", "src/tools-v2/**/*.ts"] }
```
